# Two Macs, one main branch

Two Macs (MacBook Air and Mac mini) work on the same projects at the same time. Each Mac has its own Claude account and its own compute.

## The model

- Each Mac keeps its own git clone of every repo, at the same path inside the coding folder.
- Code moves only through GitHub. Syncthing never syncs a git repo.
- Syncthing still syncs the coding folder for files that are not in a repo (notes, assets, the shared ignore list).
- Each repo has one long-lived branch: `main` (or the repo's default branch).
- Work happens on short device branches: `air/<task>` on the MacBook Air, `mini/<task>` on the Mac mini.
- Work lands on `main` only through a squash-merged pull request. The local gate result is in the PR body (GitHub Free: no CI).
- Git Town does the branch work. The shared config is `git-town.toml`, committed in each repo. The device prefix is set per Mac in the global git config.

## Why repos are not synced

Syncthing copied working files but not `.git` (ignored since 2026-11-10). Each Mac then saw the other's edits as its own uncommitted changes. Branches drifted and worktrees broke. The fix is to ignore each repo folder as a whole.

The kit writes one ignore line per repo into a marked block in `<coding>/.stglobalignore`:

```
// BEGIN mithtech-kit repos (generated by kit/scripts/stignore.mjs; do not edit inside)
/FieldOps
/frappe16/apps/erpnext
...
// END mithtech-kit repos
```

- It finds every `.git` (folder or file) at any depth. It skips `node_modules`, virtual environments and build folders. It stops at a repo root, because the parent line covers nested repos.
- It keeps every line outside the block.
- It runs from `install.mjs`, from the SessionStart hook (at most once an hour), and from the launchd job `in.mithtech.stignore` (every hour).
- `node kit/scripts/stignore.mjs --check` and `install.mjs --doctor` fail when the block is stale or a repo folder is not ignored.

Each side's `.stignore` must contain `#include .stglobalignore`.

## Setup (once per Mac)

```bash
node ~/mithtech-claude-kit/kit/install.mjs
```

The installer:
- installs Git Town (`brew install git-town`);
- adds the git aliases `git start`, `git sync`, `git ship` and `git flow-setup`;
- sets the device prefix (`air/` or `mini/`, from the host name) in `git config --global git-town.branch-prefix`; override with `--device-prefix <name>`;
- loads the hourly Syncthing ignore job.

Check it with `node ~/mithtech-claude-kit/kit/install.mjs --doctor`.

In the Claude desktop app, set the Code tab branch prefix to the same value (`air/` or `mini/`).

## Setup (once per repo)

```bash
git flow-setup
```

This writes `git-town.toml` (main branch, merge sync for feature branches, fast-forward only for main, ship through the GitHub API). Commit it through `git ship` like any other change.

## Daily flow

1. Start the session: `git sync`. This pulls `main` and merges it into your branch.
2. Start a task: `git start <task>`. This makes `air/<task>` (or `mini/<task>`) from fresh `main` and pushes it.
3. Commit as usual.
4. Finish: `git ship`. This syncs, runs the gate, opens a PR with the gate result, squash-merges it on GitHub, deletes the branch and pulls `main`.
5. If you cannot finish, push the device branch (`git sync` does it). The other Mac can continue it with `git switch air/<task>`.

Gate lookup for `git ship`: `--gate "<cmd>"`, then the first line of `.claude/gate`, then the npm `gate` script. Without a gate, ship stops. Use `--no-gate` only for repos with no checks; the PR body then says so.

`git ship --dry-run` shows what it would do.

## Rules

- Every Claude session starts with `git sync` and ends with `git ship` or a pushed device branch (rule E13).
- Never push `main` directly. Never force-push. Feature branches use merge sync, so no force-push is needed.
- Never commit a `*.sync-conflict-*` file. The guard hook blocks `git add` and `git commit` when one would be staged. Merge it by hand and delete it.
- Two Macs on the same task: each uses its own device branch. Merge one into the other only through `main`.

## Mac mini adopt

Run these steps on the Mac mini after the MacBook Air has consolidated every repo onto `main` on GitHub. Keep the Syncthing folder "coding" paused until step 4.

1. Pull the kit: `git -C ~/mithtech-claude-kit pull --ff-only`, then `node ~/mithtech-claude-kit/kit/install.mjs`. Check that the device prefix is `mini/`.
2. Install Git Town if the installer could not: `brew install git-town`.
3. Generate the ignore block before Syncthing resumes: `node ~/mithtech-claude-kit/kit/scripts/stignore.mjs`, then `node ~/mithtech-claude-kit/kit/scripts/stignore.mjs --check`.
4. Resume the Syncthing folder "coding". Wait until it is Up to Date.
5. For each repo: check that the freeze bundle in `_mini-freeze/` has every local ref (`git bundle list-heads`). Then `git fetch origin`, `git switch main`, `git reset --hard origin/main`, `git clean -fd`.
6. Delete the Mac mini worktrees (`git worktree remove`, then `git worktree prune`) and `.stversions`.
7. In the Claude desktop app, set the Code tab branch prefix to `mini/`.
8. Run `node ~/mithtech-claude-kit/kit/install.mjs --doctor`. Every git-flow line must say ok.
